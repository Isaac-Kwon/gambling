# Claude Code 프롬프트 — Education Gambling (MVP)

> 아래 전체를 Claude Code에 붙여넣는다. 기준 문서는 claude.ai 프로젝트의 `claude/project-context.md`이고, 이 프롬프트는 그 내용을 구현용으로 요약한 것이다.

## 0. 너의 역할과 작업 방식

GitHub Pages에 배포할 정적 웹 프로젝트를 처음부터 만든다. 단계(Phase)별로 진행한다.
- 각 Phase가 끝날 때마다 테스트와 빌드를 통과시키고, 커밋한 뒤 다음 Phase로 넘어간다.
- 질문이 필요한 결정은 이 프롬프트의 기본값을 따른다. 구현 중에 내린 판단은 `docs/DECISIONS.md`에 한 줄씩 기록한다.
- 이 프롬프트의 §1~§3을 `docs/CONTEXT.md`로 저장해서 저장소 안에 기준 문서를 남긴다.

## 1. 프로젝트 개요

**목적:** 개인이 어떻게 도박에 빠지는지를 체험하고 이해하게 하는 교육용 프로젝트. 실제 돈은 전혀 쓰지 않는다.

**구조:** 한 저장소, 두 페이지.
- `/gambling/` — **순수 게임.** 교육용이라는 느낌을 절대 주지 않는다. 경고, 안내, 해설, 퀴즈 문구를 넣지 않는다. 상업용 소셜 카지노 앱 수준으로 **화려하게** 만든다. 화려한 감각 자극 자체가 교육 효과의 일부다. 여러 게임이 있는 로비 구조이고, 크레딧 지갑 하나를 함께 쓴다.
- `/understanding/` — **해석.** gambling에서 기록한 세션 로그를 읽어서, 어떤 심리 장치가 언제 작동했는지, 받은 자극과 실제 손익이 어떻게 달랐는지, 플레이어의 전략이 실제로 어땠는지를 보여준다. 디자인은 차분하고 절제되게 한다. gambling과 대비되는 것도 메시지의 일부다.

**연결:** 크레딧이 바닥나거나 CASH OUT 버튼을 누르면, 게임 UI 그대로의 **정산 화면**(카지노 영수증 스타일)이 뜬다. 이 화면의 "기록 보기" 버튼이 `/understanding/`으로 이어진다. 로그는 localStorage로 넘긴다.

## 2. 기술 스택과 저장소 구조

- **Vite 멀티 페이지 + TypeScript.** 테스트는 Vitest.
- **이펙트: PixiJS v8 (WebGL)** — 기본값(미결). 네온·글로우는 CSS로 처리한다.
- **사운드:** Web Audio API로 직접 합성한다. 외부 사운드 파일은 쓰지 않는다.

- **i18n:** ko(기본) / en / it. JSON 사전 구조로 만든다. MVP에서는 ko만 채우고 나머지는 키만 만든다.

## 2.1 PWA 사양

**목표:** gambling을 휴대폰 홈 화면에 설치하면 **실제 카지노 앱처럼** 동작하게 한다. 사이트 전체가 오프라인에서도 동작하게 한다(인터넷이 불안정한 교실 대비).

- **매니페스트 1개, 스코프는 사이트 전체**(`base`). `start_url = base + "gambling/"`.
  - 그래서 설치한 앱 안에서 정산 화면 → understanding으로 넘어가도 같은 앱 창 안에서 이동한다.
  - `name`/`short_name`은 **가상 카지노 이름**으로 정한다. `description`도 게임 홍보 문구로 쓴다. 교육용 단어를 넣지 않는다(§3.2 금지어 검사 대상에 포함).
  - `display: "fullscreen"`, `display_override: ["fullscreen", "standalone"]`. 모바일 상태바의 시계까지 가려서 카지노처럼 시간 감각을 없앤다(시간 왜곡 메커니즘). 실제 표시 모드(`matchMedia('(display-mode: …)')`)를 세션 메타 `display`에 기록하고, understanding에서 "설치 앱 / 전체화면에서 플레이했음"을 해석에 반영한다.
  - `orientation: "portrait"`(기본값, 미결), `theme_color`·`background_color`는 카지노 테마의 어두운 색.
  - 아이콘: `public/icons/icon.svg`를 코드로 직접 그린다(가상 카지노 엠블럼). `scripts/gen-icons.ts`로 192, 512, maskable 512, apple-touch 180 PNG를 만든다.
- **iOS 대응:** `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style: black-translucent`, `apple-touch-icon`, 노치용 `viewport-fit=cover`와 safe-area 패딩. iOS는 `navigator.vibrate`를 지원하지 않으므로 촉각 연출은 조용히 건너뛴다.
- **서비스 워커:**
  - 모든 빌드 결과물(HTML, JS, CSS, 아이콘, i18n JSON)을 precache한다 → 첫 방문 뒤에는 완전히 오프라인으로 동작한다.
  - 네비게이션 폴백: `/gambling/*` → `gambling/index.html`, `/understanding/*` → `understanding/index.html`.
  - **업데이트 정책:** `registerType: "prompt"`로 하되 UI 알림은 띄우지 않는다. 새 서비스 워커는 대기시켜 두었다가 **다음 앱 실행 때** 적용한다. 플레이 도중 새로고침으로 세션이 끊기면 안 된다.
- **설치 유도:** gambling 로비에 `beforeinstallprompt`를 이용한 "앱 설치" 버튼을 둔다. 카지노 앱스럽게, 교육 문구 없이. iOS에서는 "홈 화면에 추가" 안내를 작은 툴팁으로 한 번만 보여준다.
- **금지 (재방문 유도 금지 원칙의 연장):** 푸시 알림, Notification API, Badging API(앱 아이콘 배지), Periodic Background Sync를 쓰지 않는다. 설치는 체험의 사실감을 위한 것이지 다시 오게 만드는 수단이 아니다.
- **저장:** 세션 로그는 기존대로 localStorage를 쓴다(설치 앱과 브라우저가 같은 origin이면 공유된다). `navigator.storage.persist()`는 요청하지 않는다.
- **understanding의 설치 앱 처리:** understanding 하단에 "이 앱을 삭제하는 방법" 안내를 둔다(Android, iOS, 데스크톱 각각). 체험이 끝난 뒤 가짜 카지노 앱이 휴대폰에 남지 않게 하기 위해서다.

## 2.2 모바일 대응 (모바일 우선 설계)

주 사용 환경은 **휴대폰 세로 화면**이다. 사람들이 도박을 처음 접하는 경로가 데스크톱이 아니라 모바일이기 때문에, 체험도 그 환경과 같아야 한다. 모든 화면을 모바일 기준으로 먼저 설계한다. 데스크톱은 보조 환경이다. 실제 모바일 카지노·소셜 카지노 앱의 조작감이 기준이다.

- **데스크톱의 gambling:** 화면 가운데 휴대폰 크기 프레임(최대 폭 약 430px, 세로 비율 유지)으로 보여주고, 바깥은 어두운 카지노 배경으로 채운다 (기본값, 미결). 데스크톱 전용 게임 레이아웃은 만들지 않는다. 마우스 클릭은 탭으로, 마우스 드래그는 스와이프로 처리한다. 스페이스 키로 스핀이나 딜을 할 수 있게 한다.
- **데스크톱의 understanding:** 넓은 화면을 활용하는 반응형 레이아웃을 쓴다(차트를 나란히 배치 등).

**레이아웃**
- 기준 폭은 360 / 375 / 390 / 414px. 최소 320px에서도 깨지지 않아야 한다. 태블릿과 데스크톱의 gambling은 위의 휴대폰 프레임 안에서 같은 레이아웃을 쓴다.
- 높이는 `100dvh`를 쓰고 safe-area(`env(safe-area-inset-*)`)를 반영한다. 노치와 홈 인디케이터에 조작 요소가 가리지 않게 한다.
- **엄지 영역:** 스핀, 딜, 베팅, 캐시아웃 등 주요 조작은 화면 하단 1/3에 둔다. 잔고와 레벨은 상단에 둔다.
- 게임별 세로 레이아웃:
  - 슬롯: 릴이 화면 폭을 꽉 채우고, 아래에 베팅 단계와 큰 스핀 버튼, 그 옆에 터보·오토 버튼.
  - 룰렛: 휠이 위, 베팅 보드가 아래. 베팅 보드는 세로로 회전한 레이아웃을 쓴다(0이 위, 숫자가 3열로 아래로 이어짐). 필요하면 확대·스크롤.
  - 블랙잭: 딜러 패가 위, 플레이어 패가 가운데, 액션 버튼(HIT/STAND/DOUBLE/SPLIT)이 하단에 한 줄.
  - 크래시: 그래프가 위, 가짜 접속자 목록은 접을 수 있는 시트, 베팅 금액·목표 배수·캐시아웃 버튼이 하단.
- 가로 모드에서도 깨지지 않게 하되, 최적화는 세로 기준으로 한다.

**터치 조작**
- 터치 영역은 최소 44×44px.
- 슬롯: 버튼 탭 외에 **릴을 아래로 스와이프해서 스핀**하는 제스처도 지원한다(통제의 착각을 강화하고 `ctl.gesture`로 기록).
- 룰렛 칩: 탭해서 칩 종류를 고르고 탭해서 놓는다. 길게 누르면 해당 칸의 칩을 회수한다.
- 더블탭 확대, 핀치 확대, 길게 누를 때 뜨는 메뉴, 텍스트 선택, 당겨서 새로고침을 게임 화면에서 막는다(`touch-action`, `overscroll-behavior: none`, `user-select: none`, `-webkit-touch-callout: none`). understanding에서는 막지 않는다.
- 탭에 대한 시각·청각 반응은 100ms 안에 나와야 한다.

**미디어**
- iOS Safari는 첫 사용자 탭 안에서 `AudioContext.resume()`을 호출해야 소리가 난다. 첫 화면에 "탭해서 시작" 같은 카지노다운 진입 화면을 둔다.
- 무음 스위치가 켜진 iOS에서는 소리가 안 날 수 있다. 오류 없이 넘어간다.
- `visibilitychange`로 앱이 백그라운드로 가면 오디오와 애니메이션을 멈추고, 돌아오면 재개한다. 오토 스핀도 백그라운드에서는 멈춘다.

**성능 예산 (중급 안드로이드 기준)**
- 목표 60fps, 최소 30fps. 첫 로딩의 gambling JS는 gzip 기준 약 250KB 이하(PixiJS 포함 목표치. 초과하면 `DECISIONS.md`에 기록).
- devicePixelRatio는 최대 2로 제한한다.
- 파티클 수에 상한을 두고, 측정된 프레임 시간에 따라 자동으로 줄인다(적응형 품질).
- understanding의 시뮬레이션은 Web Worker에서 돌리고, `navigator.hardwareConcurrency`가 낮으면 반복 횟수를 줄인다.

**understanding 모바일**
- 차트는 컨테이너 폭에 맞춰 다시 그리고, 터치로 값을 확인할 수 있게 한다.
- 긴 페이지이므로 상단에 섹션 점프 내비게이션(접을 수 있는 목차)을 둔다.

**테스트**
- Playwright 모바일 에뮬레이션(iPhone 13, Pixel 7)으로 각 게임에서 한 라운드 진행 → 정산 → understanding까지 E2E 테스트를 만든다.
- 320px과 가로 모드에서 레이아웃 스냅샷을 확인한다.

## 3. 반드시 지킬 원칙

### 3.1 무작위성
- **결과는 정직하게 무작위로 뽑고, 조작은 연출(표시)에만 둔다.** 연출은 결과가 정해진 뒤에 결정한다.
- 시드 기반 PRNG(xoshiro128** 또는 mulberry32)를 쓴다. **결과용 스트림과 연출용 스트림을 분리**해서, `?fx=off`와 켠 상태가 같은 시드에서 완전히 같은 결과를 내게 한다. 이것을 테스트로 보장한다.
- 해양 아케이드 슬롯의 "사전 결정"도 이 원칙 안에 있다. 보너스 발생 여부와 총액은 트리거 시점에 결과 스트림이 정직하게 뽑고, 그 뒤의 판들은 정해진 값을 풀어내는 것이다. 플레이어 행동에 따라 확률을 몰래 조정하는 일은 어떤 게임에서도 하지 않는다.
- 시드: URL `?seed=` 값이 있으면 그 값을 쓰고, 없으면 `crypto.getRandomValues`로 만든다.

### 3.2 gambling 번들의 순수성
- understanding용 문자열, 해설, 경고 문구가 gambling 번들에 들어가면 안 된다.
- `scripts/check-gambling-bundle.ts`를 만들어 빌드 결과물 `dist/gambling/**`와 `manifest.webmanifest`에서 금지어를 검사한다(예: "교육", "중독", "하우스 엣지", "house edge", "near-miss", "니어미스", "LDW", "1336", "바다이야기", "understanding" — 단, 정산 화면 링크 경로는 허용). 금지어가 있으면 CI를 실패시킨다.
- 로그 필드 이름도 중립적으로 짓는다. gambling 코드 안에서 `nearMiss` 대신 `dispVar` 같은 이름을 쓰고, 의미 매핑은 `/understanding/`에서만 한다.

### 3.3 안전 (필수)
- **광과민성:** 번쩍임은 초당 3회 이하(WCAG 2.3.1). 화면 전체가 빨갛게 번쩍이는 연출은 금지한다. 모든 점멸은 `flashGuard.ts`를 거치게 하고 레이트 리미터로 강제한다. 이것을 테스트로 보장한다.
- 화면 흔들림에는 진폭 상한을 둔다.
- 사운드는 사용자가 처음 상호작용한 뒤에만 켠다. 마스터 볼륨에 상한을 두고, 갑작스러운 최대 음량은 쓰지 않는다.
- `prefers-reduced-motion`이 켜져 있으면 점멸과 흔들림만 줄이고 나머지 연출은 유지한다 (기본값, 미결).
- 실제 돈, 결제, 외부 링크는 없다. 크레딧은 무료로 다시 채워진다. 리더보드, 일일 보상, 재방문 유도 장치는 넣지 않는다. 레벨·XP는 세션 안에서만 쓰고 저장하지 않는다.
- 에셋은 전부 코드로 생성하거나 직접 그린다. 상용 게임 에셋, 실존 카지노 브랜드, 로고는 쓰지 않는다. 카지노 이름은 가상으로 만든다.

## 4. 공유 계층 (`/shared/`)

### 4.1 로그 스키마 (`schema.ts`)
```ts
type Session = {
  v: 1; seed: string; mode: "free" | "class"; fx: "on" | "off";
  display: "browser" | "standalone" | "fullscreen"; installed: boolean;
  device: { w: number; h: number; dpr: number; touch: boolean; orient: "portrait" | "landscape" };
  startedAt: number; endedAt?: number; endReason?: "bust" | "cashout";
  startCredits: number; events: Ev[]; nav: { t: number; to: string }[];
};
type Ev = {
  t: number; game: "slot" | "roulette" | "blackjack" | "crash" | "ocean"; round: number;
  bet: number; payout: number; net: number; balance: number;
  disp?: Record<string, unknown>;          // 표시된 연출 정보 (예: dispVar, celebrate)
  ctl?: { stopPressed?: boolean; turbo?: boolean; auto?: boolean; gesture?: "tap" | "swipe" };
  fx?: { type: string; ms: number; k: number }[];   // 발생한 감각 연출
  dec?: Record<string, unknown>;           // 전략 관련 선택 (블랙잭 액션, 크래시 목표 배수, 룰렛 베팅 구성)
};
```
- `logger.ts`: 이벤트를 메모리에 쌓고, 라운드가 끝날 때마다 localStorage 키 `eg.session.v1`에 저장한다. 저장은 try/catch로 감싸고 실패해도 게임은 계속된다.
- `handoff.ts`: localStorage에서 읽기. 실패하면 URL 해시 `#s=`에 담긴 요약 통계(압축 + base64url)로 대체한다. 둘 다 없으면 `null`을 돌려준다.

### 4.2 규칙 엔진 (`/shared/rules/`) — 순수 함수, UI 의존성 없음
- **slot:** 5릴 × 3행, 페이라인 20개. 결과는 물리 릴 가중치로 뽑는다. 목표 RTP는 약 94%. **가상 릴 매핑:** 결과가 잭팟이 아닐 때, 연출 스트림으로 일정 확률에 따라 잭팟 심볼을 페이라인 바로 위·아래에 표시한다(`dispVar`). 베팅액보다 적은 당첨도 "당첨"으로 연출한다(LDW).
- **roulette:** 유럽식 싱글 제로. 표준 베팅(스트레이트, 스플릿, 레드/블랙, 홀/짝, 하이/로우, 더즌, 컬럼)과 배당. 엣지 2.7%.
- **blackjack:** 6덱 실제 슈, 75% 지점에서 셔플, S17, 블랙잭 3:2, 더블 다운 허용, 스플릿 후 더블 허용, 서렌더 없음. **기본 전략표를 함수로 구현**한다(`optimalAction(hand, dealerUp, rules)`). 카드 카운팅은 수학적으로 실제로 작동해야 한다. 슈 상태는 로그에 남긴다.
- **crash:** `P(crash ≥ x) = (1 − edge) / x`, edge = 1%. `crash = max(1.00, floor(100 × (1 − edge) / u) / 100)`, u ~ U(0,1). 플레이어는 목표 배수 자동 캐시아웃 또는 수동 캐시아웃을 할 수 있다.
- **ocean (해양 아케이드 슬롯, 바다이야기형):** slot의 릴 로직을 재사용한다. 매 판 결과 스트림으로 "보너스 시퀀스 트리거"를 뽑는다(낮은 확률). 트리거가 나오면 그 시점에 **보너스 총액과 풀어낼 판 수(예: 3~10판)를 결과 스트림으로 결정**하고 큐에 넣는다. 이후 판들은 큐에서 정해진 금액을 순서대로 지급한다(메모리 연타). 큐가 남아 있는 동안 플레이어의 조작은 결과에 영향을 주지 않는다. 트리거 직후 1~3판 안에 "예시" 연출 신호를 낸다. 일반 판 + 보너스 시퀀스를 합친 전체 RTP는 약 92%로 하고 rtp-check로 검증한다. 한 번의 보너스 상한은 베팅액의 1,250배(2만 원 → 250만 원 비율을 차용).
- `scripts/rtp-check.ts`: 게임마다 10⁶ 라운드를 몬테카를로로 돌려 RTP가 설계값 ±0.3%p 안에 드는지 검증한다. 블랙잭은 기본 전략으로 검증하고 엣지가 약 0.4~0.7% 범위인지 확인한다. CI에서 실행한다.

## 5. gambling 페이지

### 5.1 로비
- 가상 카지노 이름, 네온 로고(코드로 생성), 게임 카드 그리드. 카드마다 루프 애니메이션이 돈다.
- 무작위로 붙이는 "HOT" 배지, 최근 당첨 티커(가짜 닉네임과 금액). 티커의 내용은 연출 스트림으로 생성하고, 표시된 내역을 로그에 남긴다.
- 상단: 공용 크레딧 잔고(카운트업), 세션 레벨·XP 바, **CASH OUT 버튼(항상 보임)**. 시계는 어디에도 표시하지 않는다.
- 시작 크레딧은 10,000.

### 5.2 감각 자극 시스템 (`/gambling/fx/`) — 이 프로젝트의 품질 기준
| 요소 | 사양 |
|---|---|
| 당첨 등급 (`tiers.ts`) | **이번 판 베팅액 대비 배수**로만 정한다: ≥2× NICE, ≥5× BIG WIN, ≥15× MEGA WIN, ≥50× EPIC WIN. 누적 손익은 고려하지 않는다. |
| 카운트업 (`countup.ts`) | 당첨액이 숫자로 올라가며 코인 틱 사운드가 난다. 지속 시간은 당첨 배수에 비례한다(최대 약 8초, 탭하면 스킵). |
| 파티클 (`particles.ts`) | 코인 분수, 컨페티, 광선. 등급에 따라 양이 늘어난다. |
| 기대 연출 (`anticipation.ts`) | 슬롯에서 잭팟 심볼 2개 이상이 맞으면 남은 릴이 감속하고 테두리가 빛나며 심장박동 사운드가 난다. 크래시에서는 배수가 오를수록 피치가 상승한다. |
| 사운드 (`sfx.ts`) | 상승 피치 스핀음, 등급별 당첨 징글, 코인 낙하음, 저음 앰비언트 루프. 전부 합성한다. |
| 비대칭 | **손실은 무음·무연출.** 다음 판 버튼만 즉시 활성화한다. |
| 촉각 (`haptics.ts`) | 지원되는 기기에서 당첨 시 `navigator.vibrate`. |
| 속도 | 터보 토글, 오토 스핀(10/25/50/100). |
| 화면 흔들림 (`shake.ts`) | BIG WIN 이상에서만. 진폭 상한이 있다. |
- 모든 연출은 발생할 때 `fx[]`에 `{type, ms, k}`로 기록한다.
- `?fx=off`이면 연출 계층 전체를 끈다. 결과와 로직은 그대로이고, 숫자만 바뀌는 평범한 UI로 표시한다. 이 모드는 UI 어디에도 노출하지 않는다.

### 5.3 게임 (MVP 5종)
- **슬롯 (먼저 완성한다. 품질 기준점이다):** STOP 버튼이 있다. 누르면 릴이 멈추는 연출만 앞당기고 결과에는 영향이 없다(`ctl.stopPressed` 기록). 베팅 단계를 조절할 수 있다.
- **룰렛:** 칩 배치 UI, 휠 회전 애니메이션, **최근 결과 보드**(최근 20회, 빨강·검정 연속 강조). 베팅 구성은 `dec`에 기록한다.
- **블랙잭:** 딜러 애니메이션, 칩 사운드. 매 결정마다 `dec = {action, optimal, trueCountApprox}`를 기록한다. `optimal`은 기본 전략 함수로 계산하되 화면에는 절대 보여주지 않는다.
- **크래시:** 상승 곡선 그래프, 배수 카운터, 가짜 동시 접속자 목록과 그들의 캐시아웃 표시(연출 스트림으로 생성). `dec = {target, manualCashoutAt}`를 기록한다. 최근 크래시 배수 히스토리 바를 둔다.

- **해양 아케이드 슬롯 (바다이야기형, 가상 머신):**
  - 실제 제품명 "바다이야기"와 그 그래픽·캐릭터·음악은 쓰지 않는다. 가상의 이름(예: "심해전설")과 직접 디자인한 해양 생물을 쓴다.
  - 로비의 '아케이드관' 섹션에 2000년대 오락실 캐비닛 프레임(코드로 그린 베젤, 버튼 패널, 동전 투입구 장식)을 씌운다. 레트로하지만 화려하게.
  - **예시 연출:** 화면이 서서히 어두워지고, 대형 해양 생물(고래·상어·대왕조개 중 하나)이 화면을 가로지르며 저음 효과음이 난다. 등장 생물에 따라 기대감의 등급을 다르게 연출한다.
  - **연타 연출:** 큐에 든 당첨이 연속으로 터지면서 당첨 등급 연출(§5.2)이 연달아 이어진다.
  - **상품권 연출:** 큰 당첨은 크레딧 카운트업과 함께 "상품권" 종이 티켓이 기계에서 줄줄이 출력되는 애니메이션으로 보여준다(가상 디자인, 실제 상품권 디자인 모방 금지).
  - 로그: `dec = {bonusSeqId?, queued?: number, releasedFromSeq?: boolean}`, `disp.omen = "whale"|"shark"|"clam"`.

### 5.4 정산 화면 (`cashout.ts`)
- 트리거: 잔고 < 최소 베팅액(bust), 또는 CASH OUT 버튼(cashout).
- 카지노 티켓·영수증 디자인. 최종 크레딧, 플레이 시간, 최고 당첨, 플레이한 게임만 표시한다. 교육적 문구는 넣지 않는다.
- 버튼: **"상세 내역 보기"** → `/understanding/`. "다시 하기" 버튼은 MVP에서 넣지 않는다 (기본값, 미결).
- 세션을 종료(`endedAt`, `endReason`)하고 저장한 뒤 이동한다. 이동할 때 URL 해시에 요약 통계도 함께 넣는다.

## 6. understanding 페이지

절제된 타이포그래피 중심 디자인. 흰색·회색 바탕에 강조색 하나만 쓴다. 애니메이션은 최소한으로 한다.

1. **intro:** 세션 데이터를 보여주기 전에 묻는다 — "몇 분 플레이했다고 느끼나요?", "결과적으로 얼마를 따거나 잃었다고 느끼나요?" 답은 로컬에만 둔다. 로그가 없으면 "데모 세션 보기"(고정 시드로 미리 만든 로그)를 제공한다.
2. **debrief (세션 해부):** 잔고 타임라인에 기댓값 선(누적 베팅 × 하우스 엣지)을 겹쳐 그린다. 이벤트 마커(기대 연출, LDW, 큰 당첨, 손실 직후 증액)를 찍는다. 핵심 수치 카드: 니어미스 N회, 축하 연출 N회 중 실제 손실 M회, STOP 버튼 N회(영향 0), 손실 직후 베팅액 증가 N회, 최고 잔고 시점과 종료 시점, 체감 시간·손익과 실제 비교, 크레딧 손실을 원화와 최저시급으로 환산한 값.
3. **stimulus (자극 해부):** 위쪽은 연출 강도·지속 시간, 아래쪽은 누적 손익인 이중 차트. "이긴 판 연출 총 N초 / 진 판 0초"를 진 판 비율과 함께 보여준다. BIG WIN 이상이 나온 시점마다 그때의 누적 손익. 가짜 티커·HOT 배지·가짜 접속자 공개.
4. **replayPlain:** 같은 세션을 연출 없이 숫자 표로 재생한다(빠르게 넘기기 가능). 질문: "이렇게 보였어도 계속했을까요?"
5. **strategyCheck:** 블랙잭은 기본 전략 일치율과 이탈 때문에 생긴 기댓값 손실. 룰렛은 베팅 패턴 자동 감지(마틴게일, 연속 색상 반대 베팅). 크래시는 목표 배수 분포와 "어떤 배수든 RTP 99%" 시뮬레이션. 각 게임에서 "당신의 전략 vs 무작위 vs 최적"을 각각 10⁵ 라운드 시뮬레이션하고 분포를 비교한다(Web Worker 사용).
6. **sim:** 플레이어 10,000명 몬테카를로. 하우스 엣지, 라운드 수, 베팅 시스템(균등, 마틴게일, 피보나치, 달랑베르)을 슬라이더로 바꿀 수 있다. 최종 잔고 분포와 파산 비율을 보여준다.
7. **quiz:** O/X 5문항(도박사의 오류, 베팅 시스템, 니어미스, 기계가 "곧 터진다"는 믿음, 전략과 기댓값).
8. **case-badaiyagi (바다이야기 사건 해설):**
   - 사실 요약(아래 근거만 사용, 출처 링크 표기):
     - 2006년 8월 성인용 게임장이 사실상 도박 공간이 된 '바다이야기 사태'가 전국으로 번졌다.
     - 영상물등급위원회가 2005년 4월 등급 심의를 통과시켰고, 2006년 8월 성인용 게임장이 1만 5618개로 늘었다.
     - 메모리 연타: 법정 한도 2만 원의 125배인 250만 원까지 당첨되게 하고 점수를 누적해 상품권이 연속으로 나오게 한 불법 개조.
     - 예시: 화면 암전, '대합' 문양이나 고래·상어 등장 뒤 고배당 연속 당첨.
     - 경품용 상품권이 현금으로 환전되며 도박 칩 역할을 했다. 2006년 8월 한 달 유통액 약 2조 7685억 원.
     - 국무총리 공식 사과. 제조·판매사 대표 각각 징역 1년 6월.
   - 출처: 전자신문 https://www.etnews.com/20250731000108 , https://www.etnews.com/201209110606 / 한국일보 https://www.hankookilbo.com/news/article/200608202355437633 / 게임인사이트 https://www.gameinsight.co.kr/news/articleView.html?idxno=20618 / 법률신문 https://www.lawtimes.co.kr/news/24222
   - 내 세션 연결: 예시 N회와 그 시점에 이미 정해져 있던 총액, 예시 뒤 추가로 진행한 판 수와 베팅액(예시가 없던 구간과 비교), 연타 중 조작 횟수(영향 0).
   - 숫자는 사실 확인을 위해 `docs/CONTEXT.md`에 출처와 함께 정리한다. 출처에 없는 주장은 쓰지 않는다.
9. **help:** 한국도박문제예방치유원 헬프라인 **1336**. 차분한 톤으로, 페이지 하단과 debrief 끝에 둔다.

해설 문장은 사실에 근거한 짧은 문장으로 쓴다. 출처가 필요한 주장(예: 각 게임의 엣지)은 `docs/CONTEXT.md`에 근거를 정리한다.

- gambling에 교육용 문구나 경고 넣기.
