# Education Gambling — 프로젝트 컨텍스트

> 이 문서는 프로젝트의 **단일 기준 문서(Source of Truth)** 다. 어느 세션에서든 수정할 수 있다.
> 수정 규칙: (1) 결정이 바뀌면 해당 섹션을 직접 고친다. (2) 맨 아래 **변경 이력**에 한 줄을 추가한다. (3) 미결 사항이 결정되면 §8에서 §7로 옮긴다.
> 구현용 프롬프트는 `docs/BASE_PROMPT.md`에 있다. 설계 문서는 `docs/ARCHITECTURE.md`, 결정 로그는 `docs/DECISIONS.md`에 있다. 이 문서를 바꾸면 그 문서들도 함께 맞춘다.

## 1. 목표
- GitHub Pages에 올리는 **무작위성 기반 교육용 게임**. **PWA**로 만들고 **모바일 우선**으로 설계한다.
- 목적: 개인이 **어떻게 도박에 빠지는지**를 직접 체험하고, 그 메커니즘을 이해하게 하는 것.
- 원칙: 설교 대신 **"내가 방금 겪은 데이터"를 보여준다.**
- **화려한 시각·청각 자극은 꾸밈이 아니라 교육 내용 그 자체다** (§4.7).
- **휴대폰에 설치되는 카지노 앱이라는 형태 자체도 체험의 일부다** (§6.1). 실제 도박은 대부분 휴대폰에서 일어난다.

## 2. 핵심 구조: 한 저장소, 두 페이지 ✅ 확정
- 배포 주소: https://isaack.dev/gambling/ (GitHub Pages, 저장소 Isaac-Kwon/gambling). 게임 로비가 사이트 루트(`/index.html`)이고, 해석 페이지는 `/understanding/`이다. 루트 리다이렉트는 없다.

### 2.1 `/` (게임 로비, 사이트 루트) — 순수 게임
- **게임에만 집중한다.** 퀴즈, 해설, "이건 실험입니다" 같은 표시는 넣지 않는다.
- **예외 (2026-11-25 사용자 결정):** 제작 목적과 도박 중독 경고는 표시한다. 진입 화면에 "도박 중독 방지 교육용 목적으로 제작되었습니다." 한 줄, 로비 맨 아래와 설정 시트에 목적, 실제 돈 없음, 과도한 도박 경고, 한국도박문제예방치유원 ☎1336 안내 블록. 문구는 `i18n/gambling/notice.*.json`에만 두고, 번들 금지어 검사는 이 문구만 정확히 허용한다.
- **실제 상업용 모바일 카지노·소셜 카지노 앱 수준으로 화려하게 만든다** (§4.7).
- **여러 게임이 있는 카지노 로비 구조** (§4). 크레딧 지갑 하나를 모든 게임이 함께 쓴다.
- 실제 도박 기계의 심리 장치(§3)를 숨긴 채 작동시킨다.
- 내부적으로 모든 이벤트, 플레이어의 전략적 선택, 발생한 감각 자극, 기기·표시 모드를 기록한다(§5). 플레이어에게는 보이지 않는다.

### 2.2 `/understanding/` — 해석
- gambling 페이지에서 일어난 일을 **해석하고 공개**하는 페이지.
- 구성:
  1. **내 세션 해부:** 로그를 재생하며 "이 순간 이 장치가 작동했다"를 설명한다.
  2. **자극 해부 (§4.7):** 받은 자극의 양과 실제 손익을 비교하고, 같은 세션을 자극 없이 다시 보여준다.
  3. **게임별 해설:** 하우스 엣지와 RTP, 사용된 심리 장치.
  4. **전략 검증 (§4.5).**
  5. **시뮬레이터:** 몬테카를로 10,000명, 하우스 엣지 슬라이더, 파산 분포, 베팅 시스템 비교, 생존자 편향.
  6. **사전·사후 오개념 퀴즈.**
  7. **도움 연락처:** 한국도박문제예방치유원 1336 등.
  8. **설치한 앱 삭제 방법 안내** (Android / iOS / 데스크톱).
- understanding 자체는 **차분하고 절제된 디자인**으로 만든다. gambling과의 대비도 메시지의 일부다.
- 로그가 없으면 데모 세션이나 시뮬레이터로 대체한다.

### 2.3 두 페이지의 연결 ✅ 확정: (b) 게임 내 정산 화면 → understanding
- **트리거:** 크레딧 소진(잔고 < 최소 베팅), 또는 항상 보이는 **CASH OUT** 버튼.
- **정산 화면 (게임 UI 그대로):** 카지노 영수증 디자인. 최종 크레딧, 플레이 시간, 최고 당첨, 플레이한 게임만 표시. 교육 문구 없음. 버튼 **"상세 내역 보기"** → `/understanding/`, **"게임으로 돌아가기"** → 로비(같은 쿼리, 새 세션). understanding 상단과 하단에도 "게임으로 돌아가기" 링크를 둔다 (2026-11-25 사용자 결정).
- **로그 전달:** 같은 origin이므로 localStorage(`eg.session.v1`)로 넘긴다. try/catch로 감싸고, 실패하면 요약 통계를 URL 해시(`#s=...`)로 넘긴다. 수업 모드는 `?seed=`로 시드를 공유한다.
- PWA 스코프가 사이트 전체이므로, 설치한 앱 안에서도 understanding으로 같은 창에서 이동한다(§6.1).
- **understanding 진입 첫 화면:** 체감 시간과 체감 손익을 먼저 묻는다.

## 3. 재현할 메커니즘 (gambling에서 작동 → understanding에서 공개)
| 메커니즘 | gambling 구현 | understanding에서 보여줄 것 |
|---|---|---|
| 감각 자극 / 보상 연출 | 네온, 파티클, 흔들림, 카운트업, 상승음, BIG WIN (§4.7) | 자극 총량 대 실제 손익, 자극 없는 재생 |
| 승리·손실 비대칭 연출 | 승리는 요란하게, 손실은 무음·무연출 | 이긴 판과 진 판의 연출 시간 비율 |
| 변동비율 강화 | 예측 불가능한 당첨 간격 | 큰 당첨 직후 이어서 플레이한 구간 |
| 니어미스 / 기대 연출 | 가상 릴 매핑, 마지막 릴 감속, 크래시 직전 배수 | 기대 연출 N회 중 실제 당첨 M회 |
| 손실을 승리로 위장 (LDW) | 베팅액보다 적은 당첨에도 축하 연출 | 축하 연출 N회 중 실제 손실 M회 |
| 통제의 착각 | STOP 버튼, **스와이프 스핀**, 번호 선택, 카드 쪼기 | 결과에 미친 영향 0 |
| 도박사의 오류 / 패턴 읽기 | 룰렛·바카라 결과 보드 | 패턴을 보고 베팅을 바꾼 횟수 |
| 전략의 착각 | 전략 게임들 (§4.2) | 플레이어가 쓴 전략의 실제 기댓값 |
| 손실 추격 | 베팅액 자유 조절, 베팅 시스템 | 손실 직후 베팅액을 올린 횟수 |
| 화폐 추상화 | 크레딧/칩/젬 | 실제 금액·시급으로 환산 |
| 시간 왜곡 | 시계 없음, **전체화면 PWA로 상태바 시계까지 숨김**, 빠른 진행 | 체감 시간과 실제 시간 비교, 표시 모드별 해석 |
| 접근성 / 상시성 | **홈 화면에 설치되는 앱**, 오프라인 동작 | "언제 어디서나 주머니 속 카지노"의 위험 |
| 매몰비용/천장 | 가챠 천장 게이지 | 천장 때문에 계속 뽑은 구간 |
| 사회적 증거 | 가짜 잭팟 티커, 가짜 동시 접속자 | 전부 가짜였음을 공개 |
| 그만두기의 어려움 | CASH OUT이 항상 보임 | 최고 잔고 시점과 실제 종료 시점의 차이 |
| 게임 전환 | 로비에서 자유롭게 이동, "HOT" 배지 | 다른 게임으로 옮긴 패턴, 가짜 배지 공개 |
| 예시 (대박 예고) | 해양 아케이드 슬롯: 화면 암전 + 고래·상어 등장 (§4.8) | 예시 시점에 결과가 이미 정해져 있었음, 예시 뒤 추가 플레이량 |
| 메모리 연타 | 보너스가 여러 판에 나뉘어 연속으로 풀림 | 연타 중의 조작이 결과에 미친 영향 0 |
| 상품권 (화폐 세탁) | 큰 당첨을 상품권 티켓 출력으로 연출 | 2006년 경품용 상품권의 역할 |

## 4. 게임 카탈로그

### 4.1 분류 원칙 (gambling에서는 드러내지 않는다)
| 분류 | 의미 | 교육 포인트 |
|---|---|---|
| **A. 전략이 실제로 존재하지만 하우스를 이기지 못함** | 최적 플레이로 손실이 줄지만 기댓값은 여전히 음수다. | 효과가 얼마나 작은지 보여준다. |
| **B. 전략이 있다고 믿어지지만 수학적으로 무의미** | 베팅 시스템, 패턴 읽기, 타이밍. | 분산의 모양만 바꾼다. |
| **C. 순수 운** | 선택이 없거나 장식이다. | 감각 연출과 변동비율 강화. |
| **D. 사전 결정형 (예시·연타)** | 당첨이 미리 정해진 뒤 여러 판에 걸쳐 "연출"로 풀려나온다. 플레이어가 그 사이에 하는 조작은 아무 의미가 없다. | 바다이야기 사례(§4.8). "곧 터진다"는 예고가 사람을 기계 앞에 붙잡아 두는 방식. |

|---|---|---|---|---|
| **블랙잭** | A | 기본 전략, 카드 카운팅 | 기본 전략으로 약 0.5%까지 줄어든다. 카운팅은 큰 자금과 긴 시간이 필요하다. | 약 0.5% ~ 2%+ |
| **비디오 포커** (Jacks or Better) | A | 최적 홀드 | 좋은 페이테이블과 완벽한 플레이가 있어야 RTP 100% 근처. | 약 0.5% ~ 수 % |
| **바카라** | A/B | 뱅커 베팅(A), 줄타기·그림 보기(B) | 패턴 읽기는 무의미. 한국 불법 온라인 도박에서 흔함. | 뱅커 약 1.06%, 플레이어 약 1.24%, 타이 약 14% |

| **슬롯머신** | C | "곧 터진다" | 독립 시행. | 약 4~10% |
| **가챠** | C | 천장 계산 | 매몰비용 함정. | 설계값 |
| **복권 / 파워볼** | C | 번호 고르기 | 통제의 착각. | 약 40~50% |

### 4.3 A 부류 게임의 정직성 원칙
- 블랙잭은 실제 슈(6덱, 75% 지점 셔플)로 구현한다. 카운팅이 수학적으로 실제로 작동하게 둔다.
- 비디오 포커는 실제 페이테이블로 구현하고 최적 전략과 비교할 수 있게 한다.

### 4.4 로비 구성 (gambling)
- 게임 카드 그리드(루프 애니메이션), 가짜 "HOT" 배지, 가짜 당첨 티커, 공용 크레딧, 세션 레벨·XP, CASH OUT, **앱 설치 버튼**.
- 테이블 게임에는 딜러 애니메이션, 칩 소리, 결과 보드를 넣는다.

### 4.5 understanding의 전략 검증기
- 블랙잭: 기본 전략 일치율, 이탈 때문에 생긴 기댓값 손실. 비디오 포커: 홀드 비교. 룰렛·바카라: 베팅 패턴 자동 감지. 크래시: 목표 배수 분포와 RTP 동일성.
- "당신의 전략 vs 무작위 vs 최적"을 각각 10만 번 시뮬레이션해 분포를 비교한다.
- 베팅 시스템 비교: 균등, 마틴게일, 피보나치, 달랑베르.

### 4.6 서사 레이어 (선택)
- 캐릭터의 30일, Custer 모델(승리기 → 손실기 → 절망기).

### 4.7 감각 자극 설계 ✅ 확정: 화려함 = 교육 효과의 일부

#### 4.7.1 gambling에서 구현할 자극
| 범주 | 요소 | 설계 의도 |
|---|---|---|
| 시각 | 네온·글로우, 금색·빨강 팔레트, 파티클, 화면 흔들림, 광선, 배경 루프 | 각성 유지 |
| 당첨 등급 | NICE(≥2×) → BIG(≥5×) → MEGA(≥15×) → EPIC(≥50×). **이번 판 베팅 대비 배수**로만 정한다 | 누적 손해 중에도 "크게 땄다"는 느낌 |
| 카운트업 | 당첨액이 천천히 올라가고 코인 사운드. 시간은 배수에 비례 | 승리에 쓰는 시간 증가 |
| 기대 연출 | 마지막 릴 감속, 테두리 발광, 심장박동음, 크래시 상승음 | 니어미스 강화 |
| 청각 | 상승 피치 스핀음, 당첨 징글, 코인 낙하음, 앰비언트 | 조건화 |
| 비대칭 | 손실은 무음·무연출, 즉시 다음 판 | 손실을 기억에 남기지 않음 |
| 촉각 (모바일) | `navigator.vibrate` (iOS 미지원 → 건너뜀) | 신체 반응 |
| 제스처 (모바일) | 릴 스와이프 스핀 | 통제의 착각, 신체 개입 |
| 속도 | 터보, 오토 스핀 | 판단할 틈 제거 |
| 진행감 | 레벨·XP 바, 보너스 게이지 | 멈출 이유 제거 |

- 에셋은 직접 만들거나 라이선스가 명확한 것만 쓴다. 사운드는 Web Audio 합성을 우선한다.
- **슬롯 변형 (2026-11-25):** 적중률이 다른 두 변형을 구현한다. a는 적중률 약 40.6%, b는 약 30.0%이고, RTP는 둘 다 약 94%다. 숨겨진 `?sv=b`로 고른다. 최종 선택은 실제 휴대폰 비교 후 정한다 (§8).

#### 4.7.2 자극 로깅
- 연출이 발생할 때마다 `{type, ms, k}`를 그 판의 순손익과 함께 기록한다.

#### 4.7.3 understanding에서의 자극 해부
1. 자극-보상 불일치 차트 (위: 연출 강도, 아래: 누적 손익).
2. 연출 시간 비율: "이긴 판 총 N초 / 진 판 0초".
3. 등급의 착시: BIG WIN 시점마다의 누적 손익.
4. 자극 없는 재생 (숫자 표).
5. 같은 시드로 화려한 버전과 무자극 버전을 나란히 비교.
6. 체감 시간·손익 대 실제.

#### 4.7.4 무자극 모드
- 숨겨진 `?fx=off`. 결과는 같고 연출만 없다. 수업에서 두 그룹 비교 실험에 쓴다. 로그 메타에 기록한다.

#### 4.7.5 안전 한계 (필수)
- 점멸은 **초당 3회 이하**(WCAG 2.3.1). 전체 화면 빨간 점멸 금지. `flashGuard`로 강제한다.
- 흔들림 진폭 상한. 첫 상호작용 뒤에만 사운드. 볼륨 상한.
- `prefers-reduced-motion`: 점멸과 흔들림만 줄이고 나머지는 유지 (기본값, 미결).

#### 4.8.1 실제 사건 (understanding 해설의 근거, 2026-11-24 조사)
- 2006년 8월, 성인용 게임장이 사실상 도박 공간으로 변한 '바다이야기 사태'가 전국으로 번졌다. 정부가 대대적인 단속에 나섰다. (전자신문)
- **영상물등급위원회가 2005년 4월** 바다이야기를 등급 심의에서 통과시켰다. 2006년 8월에는 바다이야기, 황금성, 스크린 경마 등의 성인용 게임장이 **1만 5618개**로 늘었다. (전자신문)
- **메모리 연타:** 법정 최고 당첨 한도 2만 원의 125배인 **250만 원**까지 당첨될 수 있게 하고, 점수를 누적해 상품권이 연속으로 쏟아지게 했다. 이 기능은 불법으로 추가된 것이다. (한국일보)
- **예시 기능:** 게임 중 화면이 갑자기 어두워지면서 대박을 예고해 사람들을 기계 앞에 붙잡아 두었다. '대합' 문양이나 고래·상어 같은 동물이 나타난 뒤 당첨이 연속으로 이어졌다. (한국일보, 전자신문, Daum 블로그 인용 보도)
- **경품용 상품권:** 원래 문화상품 구입용이었는데 현금으로 환전되면서 사실상 도박 칩 역할을 했다. 2006년 8월 한 달 유통액이 약 2조 7685억 원이었다. 업계 분석으로는 사태 이전 1년간 유통액이 최소 30조 원이다. (전자신문, 게임인사이트)
- **결과:** 국무총리가 정책 실패를 공식 사과했다. 제조사와 판매사 대표는 불법 개조 혐의로 각각 징역 1년 6월을 선고받았다. (전자신문, 법률신문)

#### 4.8.2 gambling에서의 구현 (가상 머신)
- 실제 제품명 "바다이야기"와 그 그래픽·캐릭터를 쓰지 않는다. **가상의 해양 테마 아케이드 머신**으로 만든다. 이름은 "심해전설 / ABYSS LEGEND"로 확정했다(2026-11-25). 로비에 '아케이드관' 섹션을 두고 2000년대 성인 오락실 캐비닛 느낌의 프레임을 씌운다.
- **예시:** 결과 엔진이 "보너스 시퀀스"를 뽑으면 화면이 어두워지고 대형 해양 생물(고래·상어·대왕조개 등, 직접 디자인)이 지나간다. 그 다음 몇 판 뒤부터 당첨이 연속으로 나온다.
- **메모리 연타:** 보너스 총액이 여러 판에 나눠 쌓였다가 연속으로 풀려나온다. 그 사이 플레이어가 무엇을 누르든 결과는 바뀌지 않는다.
- **잔여 큐 지급:** 아직 풀리지 않은 보너스 큐는 세션 종료(CASH OUT) 때, 또는 큐가 남은 상태에서 파산 직전에 한꺼번에 지급한다.
- **상품권 연출:** 큰 당첨은 크레딧 대신 "상품권" 종이 티켓이 출력되는 애니메이션으로 보여준다. 화폐 추상화의 한국적 사례다.
- **정직성 원칙과의 관계:** 결과는 여전히 정직한 난수로 정한다. 보너스 시퀀스 발생 여부와 총액은 **트리거 시점에 RNG가 정하고**, 이후 판들은 그것을 풀어내는 연출이다. 전체 RTP는 설계값으로 고정하고 CI에서 검증한다. 이 게임은 "결과가 미리 정해지고 그 뒤의 플레이는 연극"이라는 구조 자체를 투명하게 재현한다.
- 로그: `dec.bonusSeqId`, 시퀀스 결정 시점, 예시 표시 시점, 풀려난 판 목록, 예시 뒤 플레이어가 추가로 진행한 판 수와 베팅액.

#### 4.8.3 understanding에서의 해석
- **사건 해설 섹션:** 위 사실과 출처. 심의 통과 → 게임장 급증 → 상품권 환전 → 사회적 파장의 흐름.
- **내 세션 연결:**
  - "예시가 N회 나왔다. 그 순간 결과는 이미 정해져 있었다."
  - "예시 뒤에 M판을 더 했고 X 크레딧을 더 걸었다. 예시가 뜨지 않은 구간과 비교하면 플레이 속도와 베팅액이 이렇게 달랐다."
  - "연타가 풀리는 동안 STOP·베팅 변경 N회, 결과에 미친 영향 0."
- **오늘과의 연결:** 같은 구조가 온라인·모바일 불법 도박으로 옮겨 왔을 수 있음을 다룬다. 구체적인 주장은 출처를 확인한 뒤에만 쓴다.

## 5. 무작위성 설계 원칙
- **결과는 정직하게 무작위로 뽑고, 조작은 연출(표시)에만 둔다.** 연출은 결과가 정해진 뒤에 결정한다.
- 시드 기반 PRNG. **결과용 스트림과 연출용 스트림을 분리**한다 (fx on/off에서 결과 동일).
- 모드: 자유(무작위 시드) / 수업(고정 시드).
- **로그:**
  - 세션 메타: `seed, mode, fx, display(browser|standalone|fullscreen), installed, device{w,h,dpr,touch,orient}, endReason`, 게임 전환 이력.
  - 라운드 공통: `t, game, round, bet, payout, net, balance, disp`
  - 조작: `ctl{stopPressed, turbo, auto, gesture(tap|swipe)}`
  - 자극: `fx[]`
  - 전략: `dec` (블랙잭 액션·최적 액션, 크래시 목표, 룰렛 베팅 구성)
- gambling 코드 안의 필드 이름은 중립적으로 짓는다(예: `nearMiss` 대신 `dispVar`). 의미 매핑은 understanding에서만 한다.

## 6. 기술 스택 / 저장소 구조
- Vite 멀티 페이지 + TypeScript + Vitest, Playwright(모바일 E2E). GitHub Actions → Pages.
- 이펙트: PixiJS v8 + CSS 글로우. Pixi는 장식 레이어(파티클, 광선, 글로우)만 그리며, "탭해서 시작" 게이트 뒤에 지연 로드한다. 릴·카드·보드·텍스트는 DOM/SVG로 그린다. 사운드: Web Audio 합성. 차트: uPlot.
- i18n: ko / en / it.
- 서버 없음, 외부 요청 없음, 분석 도구 없음.
- `/shared/`: rng, schema, logger, handoff, 규칙 엔진(`/shared/rules/`, 순수 함수). understanding의 시뮬레이터가 같은 규칙 엔진을 재사용한다.
- CI: RTP 검증(정확 계산 + 몬테카를로, 결과가 이론값에서 표준오차 4배 이내. 10⁶ 라운드 ±0.3%p는 슬롯 검증에 통계적으로 부족해 폐기), gambling 번들과 매니페스트 금지어 검사, flashGuard 테스트, fx on/off 결과 일치 테스트, 모바일 E2E.

### 6.1 PWA ✅ 확정
- `vite-plugin-pwa`(Workbox generateSW).

### 6.2 모바일 대응 ✅ 확정 (모바일 우선)
- **근거:** 사람들이 도박을 처음 접하는 경로는 데스크톱이 아니라 모바일이다. 그래서 체험도 도박을 실제로 처음 만나는 환경과 같아야 한다. 데스크톱은 보조 환경이다.
- 데스크톱에서는 gambling을 **화면 가운데 휴대폰 크기 프레임**으로 보여준다 (기본값, 미결). 모바일 체험을 그대로 유지하고, 레이아웃을 따로 만들 부담도 줄이기 위해서다. understanding은 데스크톱에서 넓은 레이아웃을 써도 된다.
- **주 환경은 휴대폰 세로 화면.** 기준 폭 360/375/390/414px, 최소 320px. 태블릿과 데스크톱의 gambling은 휴대폰 프레임 안에서 같은 레이아웃을 쓴다.
- `100dvh`, safe-area 반영. **엄지 영역(하단 1/3)에 주요 조작**을 둔다.
- 게임별 세로 레이아웃: 슬롯(릴이 폭 전체, 하단 큰 스핀 버튼), 룰렛(휠 위, 세로로 회전한 베팅 보드 아래), 블랙잭(하단 액션 한 줄), 크래시(그래프 위, 접속자 목록은 접는 시트).
- 터치 영역 최소 44px. 슬롯 스와이프 스핀. 룰렛 칩은 탭으로 놓고 길게 눌러 회수.
- 게임 화면에서는 더블탭·핀치 확대, 길게 누르기 메뉴, 텍스트 선택, 당겨서 새로고침을 막는다. **두 손가락 확대는 understanding에서도 막는다** (2026-11-25 사용자 결정: viewport `maximum-scale=1, user-scalable=no`, `touch-action: pan-x pan-y`, iOS용 `gesturestart`와 다중 터치 `touchmove` 취소, `shared/nozoom.ts`).

## 7. 확정된 결정 / 윤리 안전장치
- ✅ 한 저장소, 두 페이지(`/` 게임 로비, `/understanding/`).
- ✅ gambling은 교육 요소 없이 게임에만 집중한다. 해석, 공개, 퀴즈는 understanding에 둔다. 단, 제작 목적 문구와 도박 중독 경고, 1336 안내는 진입 화면, 로비, 설정에 표시한다 (2026-11-25, §2.1).
- ✅ 정산 화면과 understanding에서 게임으로 돌아갈 수 있다 (2026-11-25, §2.3).
- ✅ 연결 방식 (b): 크레딧 소진 또는 CASH OUT → 정산 화면 → understanding.
- ✅ 다중 게임 로비. 전략이 통한다고 알려진 게임도 포함한다. A 부류는 실제 확률 구조로 구현한다.
- ✅ gambling은 상업용 수준으로 화려하게 만든다. 자극을 로깅하고 해부한다.
- ✅ 결과용·연출용 난수 스트림 분리.
- ✅ 광과민성 안전 한계.
- ✅ **PWA**: 사이트 전체 스코프, 전체화면 표시, 완전 오프라인, 다음 실행 시 업데이트. 푸시·배지·백그라운드 동기화 금지. understanding에 앱 삭제 안내.
- ✅ **모바일 우선 설계**: 세로 화면 기준, 엄지 영역 조작, 터치 제스처, 성능 예산, 모바일 E2E.
- ✅ **바다이야기 케이스 포함** (§4.8): gambling에는 가상 해양 아케이드 머신으로 예시·메모리 연타·상품권 연출을 재현하고, understanding에 출처를 붙인 사건 해설을 둔다. 실제 제품명과 그래픽은 쓰지 않는다.
- ✅ **MVP 게임 범위:** 로비 + 슬롯(C) + 룰렛(B) + 블랙잭(A) + 크래시(B) + 해양 아케이드 슬롯(D). 해양 아케이드 슬롯은 일반 슬롯의 릴·이펙트 엔진을 재사용한다.
- ✅ **이펙트:** PixiJS v8 유지. Pixi는 장식 레이어만 그리고 "탭해서 시작" 뒤에 지연 로드한다. 릴·카드·보드·텍스트는 DOM/SVG다.
- ✅ **루트:** 게임 로비가 사이트 루트(`/index.html`). 루트 리다이렉트 없음.
- ✅ **가상 이름:** 카지노 "오로벨 카지노 / OROBELLE CASINO", 해양 아케이드 머신 "심해전설 / ABYSS LEGEND".
- 실제 돈, 결제, 외부 링크 없음. 크레딧은 무료 재충전. 리더보드·일일 보상 없음. 레벨·XP는 세션 안에서만.
- 에셋은 직접 제작 또는 명확한 라이선스.

## 8. 미결 사항
- [ ] 대상: 중고생 / 대학생 / 일반?
- [ ] 사용 환경: 수업용 / 개인 접속용?
- [ ] `prefers-reduced-motion` 처리 (현재 기본값: 점멸·흔들림만 줄임).
- [ ] PWA 방향 고정: 세로 고정(현재 기본값) vs 자유 회전.
- [ ] 데스크톱의 gambling 표시: 휴대폰 크기 프레임(현재 기본값) vs 데스크톱 전용 레이아웃.
- [ ] 가상 스포츠 베팅 포함 여부.
- [ ] 블랙잭 연속 셔플 모드 추가 여부.
- [ ] 세션 상한과 게임 내 처리 방식.
- [ ] 서사 레이어 포함 여부.
- [ ] 이탈리아 도움 연락처 추가 여부 (번호 확인 필요).
- [ ] 슬롯 변형 a/b 최종 선택 (`?sv=b`, 실제 휴대폰 비교 후).
